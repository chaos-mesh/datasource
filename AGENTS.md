# Agent guideline

This repository contains the Chaos Mesh Grafana data source plugin. It is a TypeScript and React frontend plugin. HTTP requests reach the Chaos Dashboard API through Grafana's data source proxy. There is no plugin backend.

## Find the owning code

- `src/module.ts` registers the data source and its editors.
- `src/datasource.ts` owns event queries, data frames, connection checks, variable queries, and annotations.
- `src/types.ts` defines event and query models. `src/utils.ts` handles template variables and multi-value query expansion.
- `src/components/` contains the configuration, query, and variable editors. Reuse Grafana UI components and existing editor patterns.
- `src/plugin.json` declares plugin metadata and the minimum Grafana version.
- `e2e/` contains Playwright compatibility tests, the HTTP API fixture, test provisioning, and a Grafana Compose configuration.

Keep compatibility migrations separate from unrelated behavior changes. Add only the tests needed for the changed behavior.

Every commit must include a DCO `Signed-off-by` trailer. Use `git commit -s` for new commits and include `-s` when amending commits.

## Maintain the official scaffold

The `.config/` directory is generated by `@grafana/create-plugin`. Its version is recorded in `.config/.cprc.json`.

- Use the official `@grafana/create-plugin` update command for scaffold upgrades. Inspect its dependency and workflow changes before keeping them.
- Put project-specific configuration in root-level extensions when the scaffold supports them. Avoid hand-maintaining generated base files.
- Keep the Grafana SDK version aligned with the minimum supported host. Installing a newer SDK does not prove compatibility with older Grafana hosts.
- Preserve the shared React, JSX runtime, and Grafana dependencies configured as build externals. Grafana provides these at runtime.
- Check `src/plugin.json`, `README.md`, local Grafana defaults, and the CI version matrix together when changing compatibility.
- Build `dist/` from source. Do not edit generated bundles or commit local build and test output.

## Write GitHub release notes

Follow the format of the corresponding version entry in `CHANGELOG.md`. Keep its category headings, Markdown heading levels, and entry order, including headings such as `### Fixed`. After publishing or editing the release, check the notes on GitHub.

## Develop and validate

Use the Node.js version in `.nvmrc` and the pnpm version in `package.json#packageManager`. Use pnpm and keep `pnpm-lock.yaml` synchronized with dependency changes.

For source or toolchain changes, run:

```sh
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm run lint
pnpm run build
```

Run `pnpm run test:ci` for query or annotation changes. Add only the regression tests needed for the changed behavior. For documentation-only changes, check formatting and verify referenced paths and commands.

For Grafana API, dependency, or bundler changes, run the browser suite against the stable Grafana versions resolved from `src/plugin.json` by the official version resolver in `.github/workflows/ci.yml`:

```sh
pnpm exec playwright install chromium
docker compose -f e2e/docker-compose.yaml up -d --build
curl --fail --retry 30 --retry-connrefused --retry-delay 1 http://127.0.0.1:3002/api/health
pnpm run e2e
docker compose -f e2e/docker-compose.yaml down --volumes
```

Set `GRAFANA_VERSION` on the Compose command to select a host version. Set `GRAFANA_URL` for a different browser target. Playwright starts the fixture API on port 23033. The fixture enforces the test-only authorization header configured in `e2e/provisioning/`.

For real Chaos Mesh validation, use an existing instance or follow the [official Helm installation guide](https://chaos-mesh.org/docs/production-installation-using-helm/). Generate events with an experiment scoped to a dedicated test workload before checking query results.

Configure the Grafana data source URL and authentication for the real Dashboard API. `CHAOS_MESH_LIVE=1` disables fixture startup and fixture-specific assertions; it does not switch the data source URL. Set `CHAOS_MESH_TEST_NAMESPACE` and `CHAOS_MESH_TEST_EXPERIMENT` to the dedicated test resources. Grafana containers must use an API address reachable from inside the container.

For query, variable, or annotation changes, verify the affected behavior in Grafana. Report which checks used the fixture API, real Chaos Mesh, containers, or CI, and whether signing ran.

## Reuse caches and clean up owned resources

- Before installing dependencies, inspect the project configuration and effective cache paths, including `pnpm store path`. Reuse an existing project or shared dependency store.
- Do not create a new dependency or browser download cache for a task, branch, worktree, or subagent. Do not put download caches in temporary evidence directories.
- Share dependency downloads while isolating source, test output, and runtime state. Reuse tool archives and container layers by version.
- If sandbox permissions block a shared cache, request access to that cache rather than silently creating a temporary replacement. Record any necessary exception and its cleanup plan.
- Give delegated work the same selected cache paths. Coordinate dependency installs and shared file writes.
- Use a dedicated namespace and explicit selectors for local chaos experiments. Clean up only resources created for the task, including processes, containers, mounts, and disposable runtime data. Preserve shared caches and existing cluster resources. Do not run a global Docker prune.
